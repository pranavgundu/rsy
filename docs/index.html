Abstract

This document describes rsy, a Rust file synchronization tool designed for fast local copies, SSH transfers, and daemon-style rsync:// targets. The implementation combines parallel file-list construction, size/mtime short-circuiting, rolling-checksum delta transfer, platform copy-on-write primitives, and an interactive progress UI. The current release process also requires CI to pass before any CD build or package publish job can proceed.

1. Transfer Model

Let $F$ be the number of regular files, $D$ the number of directories, $L$ the number of symbolic links, and $B = \sum_{i=1}^{F} b_i$ the total source byte mass. The observable runtime is decomposed as

$$ T = T_{walk} + T_{filter} + T_{meta} + T_{copy} + T_{delta} + T_{ui}. \tag{1} $$

For a cold destination, $T_{delta}$ is intentionally negligible because files without a basis take the whole-file path. For a warm destination, $T_{copy}$ is often zero because unchanged files are rejected by size and modification time unless --checksum requests byte-level comparison.

Invariant 1. A regular file is skipped when size and mtime match. If --checksum is enabled, equality is determined by file content hash instead. If --update is enabled, a newer destination file is preserved.

2. Accepted Path Forms

The parser classifies a command into exactly one transfer mode. The destination is checked first for daemon syntax, then SSH push syntax; the source is checked for SSH pull syntax after that. This ordering prevents rsync:// and host::module destinations from being mistaken for SSH paths.

Table 1. Path forms accepted by rsy.
Form Mode Meaning
rsy SRC/ DST/ Local Copy or synchronize within the local filesystem namespace.
rsy SRC/ host:/path/ SSH push Start a remote rsy receiver over SSH and send source data.
rsy host:/path/ DST/ SSH pull Start a remote rsy sender over SSH and receive data locally.
rsy SRC/ rsync://host/module/path Daemon push Connect to the daemon transport and push to the module path.
rsy SRC/ host::module/path Daemon push Use rsync module syntax with the default daemon port.

Trailing slash behavior follows the rsync convention: SRC/ copies the contents of SRC, while SRC copies the directory itself under the destination.

3. Synchronization Algorithm

3.1 File list and filtering

A source file list is built in parallel. When --delete is not requested, the destination tree is not inventoried, avoiding a full extra walk. Include and exclude rules are evaluated in command order, with the first matching rule deciding the outcome. Directory patterns ending in / also affect descendants.

3.2 Path confinement

Received relative paths are lexically cleaned. Absolute paths, parent-directory traversal, and symlinked destination ancestors are rejected before writes occur. Symbolic link targets must also be relative and must not escape through leading .. components.

3.3 Cold copy and delta update

For new files, rsy uses fast whole-file copying. On macOS it attempts APFS clonefile(); on Linux it attempts FICLONE reflinks; when unsupported, it falls back to a normal copy. Existing files use the delta path unless --whole-file, very large file limits, or empty basis conditions make whole-file replacement cheaper.

$$ S_{cold} = \frac{F\alpha_{meta} + \alpha_{rw}B}{F\beta_{meta} + \beta_{copy}B}. \tag{2} $$

Equation (2) models the cold-copy speedup from lower metadata overhead and more efficient kernel copy paths. For same-volume copy-on-write filesystems, $\beta_{copy}$ approaches a metadata operation rather than a byte-by-byte transfer.

Proposition 1. If a destination basis exists and only a fraction $\rho$ of bytes changed, an ideal delta transfer sends $\rho B$ literal bytes and references $(1 - \rho)B$ matched bytes. rsy's rolling checksum stream approximates this by emitting Data and Copy tokens against block signatures. $$ B_{wire} \approx \rho B + O(F + B / q), \tag{3} $$ where $q$ is the selected block size.

3.4 Output modes

rsy selects the TUI when stderr is a terminal and neither --no-tui, --dry-run, nor --log disables it. Plain mode prints a summary; log mode prints timestamped per-file activity. A partial transfer exits with code 23.

4. Command-Line Surface

Transfer control

-a, --archivePreserve times, perms, owner, group, and symlinks.
--deleteRemove destination entries missing from the filtered source list.
-u, --updateSkip files when the destination is newer.
--ignore-existingLeave existing destination files untouched.
-W, --whole-fileUse whole-file replacement instead of delta tokens.
--inplacePatch destination directly instead of atomic temp-and-rename.
-xDo not cross filesystem boundaries.

Filtering and output

--include PATTERNAdd an include rule.
--exclude PATTERNAdd an exclude rule.
--exclude-from FILERead exclude rules, ignoring blanks and comments.
--max-size SIZESkip files larger than a byte/K/M/G/T value.
--min-size SIZESkip files smaller than a byte/K/M/G/T value.
--logTimestamped stderr logging, no TUI.
--statsPrint final transfer statistics.
 
npm install -g @gundu/rsy
cargo install rsy

rsy -a ./site/ /backup/site/
rsy --delete --exclude target --exclude .git ./project/ /mnt/project/
rsy -az ./media/ user@example.com:/srv/media/
rsy --checksum --stats ./src/ ./dst/
Compatibility note. --compress is accepted for CLI compatibility but is not implemented yet; the command continues without compression and emits a warning.

5. Release Logic

Version 1.1.3 publishes one main npm package and five platform packages: @gundu/rsy-linux-x64, @gundu/rsy-linux-arm64, @gundu/rsy-darwin-x64, @gundu/rsy-darwin-arm64, and @gundu/rsy-win32-x64. The Rust crate version, Cargo lock entry, npm package version, and optional dependency versions are kept equal.

The CD workflow is tag-triggered by v*, but release builds are now gated by an explicit CI job. The release build matrix cannot start until formatting, clippy, release build, and release tests pass.

$$ CD_{publish} = CI_{ok} \land Build_{matrix,ok}. \tag{4} $$ 
ci:
  cargo fmt --check
  cargo clippy --locked --all-targets -- -D warnings
  cargo build --locked --release
  cargo test --locked --release

build:
  needs: ci

6. Benchmark Interpretation

The benchmark suite compares cold sync, no-change incremental sync, and partial-change delta sync against rsync and cp. It uses Criterion and generated corpora. Because the benchmark constructs temporary source and destination trees with tempfile::TempDir, benchmark I/O can be moved to a specific volume by setting TMPDIR before running cargo bench. 

mkdir -p "/Volumes/PG Drive/rsy-bench-tmp"
TMPDIR="/Volumes/PG Drive/rsy-bench-tmp" cargo bench
Table 2. Representative README benchmark results.
Scenario rsy rsync comparison Interpretation
10k files x 4 KB cold copy 126 ms 3.83x faster Small-file metadata parallelism dominates.
500 files x 1 MB cold copy 35 ms 7.77x faster Parallel I/O keeps workers saturated.
10 files x 10 MB, 10% changed 1.4 ms 31.43x faster Rolling-checksum delta minimizes patch work.

7. Verification Surface

The test suite currently covers checksum behavior, delta round trips, filter semantics, parser mode detection, path confinement, local sync options, protocol limits, dry-run behavior, deletion, min/max-size filtering, update preservation, and whole-file replacement. The unit suite reports 69 binary tests.
